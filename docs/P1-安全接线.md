## 二、环境变量与状态文件

| 变量 | 默认 | 作用 |
|---|---|---|
| `PROXY_DEVICE_AUTH=1` | 关 | 启用设备密钥鉴权（只保护 API 路径，见第四节） |
| `PROXY_DEVICE_AUTH_STRICT=1` | 关 | 连回环客户端也要求设备密钥；**仅用于测试/验证** |
| `PROXY_RATE_CAPACITY` | `60` | 按 IP 的令牌桶容量；非法/非正数回落 60 |
| `PROXY_RATE_REFILL_PER_SEC` | `2` | 每秒补充的令牌数（支持小数）；非法/非正数回落 2 |
| `PROXY_STATE_DIR` | 代理脚本目录下 `logs/` | 沿用已有变量；下表的文件都落在这里 |

状态文件（由 `src/core/security.js` 管理）：

```
<PROXY_STATE_DIR>/devices.json   设备注册表（同文件模式也存配对码；只存 sha256）
<PROXY_STATE_DIR>/audit.jsonl    审计 JSONL（5 MiB 轮转，保留 .1/.2）
```

启动日志会打印（示例，严格模式）：

```text
  设备鉴权: 开(严格：回环也校验)
  设备注册表: ...\devices.json
  审计: ...\audit.jsonl
  限流: 按 IP，容量 60，补充 2/秒
```

未开设备鉴权时打印 `设备鉴权: 关`；开了但未 strict 时打印
`设备鉴权: 开(回环豁免)`。

## 三、端点

新增端点全部 `Cache-Control: no-store`，错误统一为
`{ "ok": false, "error": "<code>" }`（HTTP 状态仍表达类别）。

| 方法 | 路径 | 鉴权 | 限流 | 成功响应 |
|---|---|---|---|---|
| POST | `/_pair` | 公开（配对的设备还没有 key） | 是 | `{ok:true, deviceId, key, name}`，`key` 只返回这一次 |
| GET | `/_security/devices` | 复用 `bridgeAuthorized(req)` | 是 | `{ok:true, devices:[{id,name,prefix,createdAt,lastUsedAt,revokedAt}]}`（无明文 key/hash） |
| POST | `/_security/pairing` | 同上 | 是 | `{ok:true, code:"6 位数字", expiresAt}`，`code` 只返回这一次 |
| POST | `/_security/revoke` | 同上 | 是 | body `{id}`；`{ok:true, deviceId, device, alreadyRevoked}`；未知 id → 404 `not_found` |
| POST | `/_security/rotate` | 同上 | 是 | body `{id}`；`{ok:true, deviceId, key, name}`，新 `key` 只返回这一次；revoked/expired → 409，未知 → 404 |

错误码：

| HTTP | error | 触发 |
|---|---|---|
| 400 | `invalid_json` | 请求体不是合法 JSON 对象（`/_pair` 同时记审计 `pair_redeem_fail`） |
| 400 | `invalid_request` | `revoke`/`rotate` 缺 `id` |
| 401 | `unauthorized` | `/_pair` 兑换失败（malformed/no-pairing/expired/invalid-code/max-attempts 不区分）；`/_security/*` bridge token 不对 |
| 404 | `not_found` | 未知 `/_security/*` 子路径；revoke 未知设备；rotate 未知设备 |
| 405 | `method_not_allowed` | 方法不对 |
| 409 | `revoked` / `expired` | rotate 目标不可轮换 |
| 429 | `rate_limited` | 限流（带 `Retry-After`，见第五节） |
| 500 | `internal` | 注册表/配对文件读写异常（响应不暴露异常文本） |

**`bridgeAuthorized` 语义未改**：未设置 `PROXY_TOKEN` 时返回 true，因此
`/_security/*` 与 `/_bridge/*` 一样免鉴权。生产环境依赖外壳生成 `PROXY_TOKEN`；
手工运行代理做设备管理时必须自己设置它。

## 四、设备鉴权精确规则

仅在 `PROXY_DEVICE_AUTH=1` 时生效。

1. **保护路径**（只有这些）：
   - `/v1/` 前缀（含 `/v1/chat/completions`、`/v1/models` 等）；
   - `/props`、`/tokenize`、`/embedding`、`/slots`（`/slots` 更早已经 404）。
2. **静态页面/HTML/面板脚本不要求设备 key**：`/`、`/<面板脚本>`、
   `/_bridge/status`、`/_bridge/config` 全部沿用原有行为，否则手机页面打不开。
3. **回环豁免**：`req.socket.remoteAddress` 是 `127.0.0.1`、`::1`、
   `::ffff:127.0.0.1`（以及 `127.0.0.0/8`、`::ffff:127.x`）且未设
   `PROXY_DEVICE_AUTH_STRICT=1` → 直接放行，Authorization 原样保留，
   但 `x-device-key` 会被删除、不透传上游。
4. **取 key**：优先 `x-device-key: <key>`，其次 `Authorization: Bearer <key>`
   （`bearer` 大小写不敏感）。
5. **校验**：`registry.verifyKey(key, { ip })`（sha256 + 常量时间比较）。
6. **成功**：审计 `auth_ok`（含 `deviceId`、`ip`、方法/路径）；转发前
   - 删除 `x-device-key`；
   - `UPSTREAM_KEY` 非空 → `Authorization: Bearer <UPSTREAM_KEY>`；
   - `UPSTREAM_KEY` 为空 → 删除 `Authorization`。
   这样客户端永远看不到 llama-server 的 API key，上游日志里也不会出现设备 key。
7. **失败**：401 `{ok:false,error:'unauthorized'}`；审计 `auth_fail`，`detail`
   只写 `invalid/missing/revoked/expired + 方法 + 路径`，响应不回显原因。

顺序：`/v1/*` 限流 → 设备鉴权 → 读请求体 → 压缩 → 转发。未通过鉴权的请求
不会读请求体，也不会到达上游。`/_bridge` 的鉴权顺序与 P0 完全一致。

## 五、限流精确规则

只有一个令牌桶限流器（`createRateLimiter`），**key 就是来源 IP 字符串**
（`req.socket.remoteAddress`，不取 X-Forwarded-For）。容量/补充速率来自
`PROXY_RATE_CAPACITY` / `PROXY_RATE_REFILL_PER_SEC`。

| 路径 | 限流位置 |
|---|---|
| `/_pair` | 进入 handler 的第一步（公开端点，先限流再解析方法/请求体） |
| `/_security/*` | `bridgeAuthorized` 通过之后 |
| `/v1/*` | 设备鉴权之前 |

同一个 IP 的配对、管理、`/v1` 请求**共用**一个桶（按任务要求 key=IP）。
被拒绝时：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: <秒>
Cache-Control: no-store

{"ok":false,"error":"rate_limited"}
```

`Retry-After = max(1, ceil(retryAfterMs / 1000))`。审计写 `rate_limited`，
同一 IP 每 5 秒最多一条（内存节流，避免 429 刷爆日志）；因此审计里的
`rate_limited` 条数少于实际 429 次数是有意的。

## 六、审计

`createAuditLog({ file: <PROXY_STATE_DIR>/audit.jsonl })`，JSONL，一行一个
对象，字段 `ts/event/deviceId?/ip?/detail?`。

| 事件 | 触发 | detail 内容 |
|---|---|---|
| `auth_ok` | 设备 key 校验通过 | `方法 路径` + `deviceId` |
| `auth_fail` | 设备 key 缺失/错误/吊销/过期 | `原因 方法 路径`（原因只进审计） |
| `pair_create` | `POST /_security/pairing` 成功 | `POST /_security/pairing` |
| `pair_redeem_ok` | `POST /_pair` 成功 | `POST /_pair` + `deviceId` |
| `pair_redeem_fail` | 兑换失败（含非法 JSON） | `POST /_pair 原因` |
| `revoke` | `POST /_security/revoke` 成功 | `POST /_security/revoke` + `deviceId` |
| `rate_limited` | 429 | `方法 路径`（5 秒/IP 节流） |
| `rotate`（额外） | `POST /_security/rotate` 成功 | `POST /_security/rotate` + `deviceId` |

硬约束：

- **绝不**写请求体、prompt、对话内容、请求头、明文设备 key、上游 API key；
  测试用含 `SECRET_PROMPT` 的请求体断言 `audit.jsonl` 不含该串，也不含设备 key。
- 明文设备 key / 配对码只出现在 HTTP 成功响应里一次，不落盘（注册表只存
  sha256；配对码只存 salt + sha256）。
- 审计写失败（磁盘满/权限）只记外壳日志，不影响已经通过鉴权的请求。
- 轮转与坏行容错由 `src/core/security.js` 负责（默认 5 MiB，保留 `.1`/`.2`）。

## 七、测试与验收

新增 `tools/test_security_wiring.mjs`：真实启动代理子进程 + 假上游，使用临时
`PROXY_STATE_DIR`、固定端口区间与 `PROXY_DEVICE_AUTH_STRICT=1`，覆盖任务里的
1–8 项，共 **64 项断言**：

1. `/_security/pairing`：无 token 401、带 token 200、6 位 code、审计 pair_create；
2. `/_pair`：兑换 200 返回 deviceId/key、同码第二次 401、审计 ok/fail、非法 JSON 400；
3. `/v1`：无 key 401 且不到上游、`x-device-key`/Bearer 200、错误 key 401、
   上游只看到 `UPSTREAM_KEY`、看不到设备 key；
4. 非 strict 回环豁免：`PROXY_DEVICE_AUTH=1` 下 127.0.0.1 的 `/v1`、`/props`
   与页面都 200；
5. 限流：容量 3 + refill 0.001 时前 3 次 200、第 4 次 429、`Retry-After` 合法、
   连续 429 时审计 5 秒内只有 1 条；
6. 吊销/轮换：rotate 返回新 key、旧 key 立即 401、revoke 后立即 401、
   列表带 `revokedAt`、审计 revoke；
7. 原有安全项：`/slots` `/metrics` 404、8 MiB 413 且不转发、bridge 无 token 401、
   HTML 注入面板与 token、未开设备鉴权时 `/v1` 不需要 key；
8. 审计不含 `SECRET_PROMPT`、设备 key、`UPSTREAM_KEY`；敏感内容请求本身 200。

## 八、未解决 / 已知限制

- **main.js / UI 未接线**：外壳不会传 `PROXY_DEVICE_AUTH`，也不会调用
  `/_security/*`；本阶段只完成代理层。设备管理入口留待下一步的 IPC/设置页。
- **`PROXY_TOKEN` 为空时管理端点免鉴权**：这是复用 `bridgeAuthorized` 的既有
  语义（任务要求不改）。生产必须依赖外壳生成的 token；手工运行时要显式设置。
- **回环豁免不是用户边界**：本机进程不需要设备 key。P1 的威胁模型本来就是
  「同一局域网的其他设备」，能读本机文件的攻击者不在防线内。
- **限流只有内存态**：进程重启清零；key 只有 IP（NAT 后多设备共享）；
  `/_pair`、`/_security/*`、`/v1/*` 共用一个桶；大量伪造来源可按核心模块的
  已知 LRU 缺陷挤掉旧桶。
- **`rate_limited` 审计被 5 秒/IP 节流**：日志条数少于实际拒绝次数。
- **无 TLS**：LAN 上设备 key/配对码可能被同网段嗅探；LAN 模式仍应保留
  llama-server 的 `--api-key` 作为最后一道锁。
- **审计不是防篡改账本**：无 fsync、无哈希链，本机可改/删；只用于运行诊断。
- **设备数量没有硬上限**，长时间运行可让 `devices.json` 增长；管理端点需要
  bridge token 才能创建。
- **单进程单写者假设**（继承 P1 核心）：两个代理进程指向同一状态目录会互相
  覆盖 `devices.json` / `audit.jsonl`。
- **回环识别范围**：目前识别 `127.0.0.0/8`、`::1`、`::ffff:127.x`；其它
  代理头（如真实的局域网地址）都按需要设备 key 处理。

## 二、A. catalogue IPC 新增字段（main.js）

`src/main.js` 新增两个只读 helper：

- `buildBinarySummary()`：当前默认构建摘要；
- `catalogueEnvironment()`：一次算出 `modelRoots` / `suggestedModelRoot` /
  `buildRoots` / `buildBinary`。

`ipcMain.handle('catalogue')` 的返回值**只加不删**，原有全部字段保持原样：

| 字段 | 类型 | 说明 |
|---|---|---|
| `modelRoots` | `string[]` | `paths.modelRoots.slice()`；环境变量 `MODEL_STOVE_MODELS` > `config.models.roots` > 自动建议根 |
| `suggestedModelRoot` | `{ root: string, source: string, candidates: number } \| null` | `paths.suggestedModelRoot` 的摘要；**只给候选盘数量**，不含 `candidates` 数组里的 `freeBytes` 等明细 |
| `buildRoots` | `string[]` | `paths.buildRoots.slice()`（`MODEL_STOVE_BUILDS` / `config.builds.roots`） |
| `buildBinary` | `{ path: string \| null, present: boolean }` | `BIN.stock` 存在即用；否则取 `runtimeModels()` 里第一个存在的 bin；都不存在时 `present=false`，`path` 保留 `BIN.stock` 的配置值（若有） |

实现要点：

- `catalogueEnvironment()` 在 `paths` 为空时先 `initRuntime()`，保证 IPC 早于
  `whenReady` 时也不会返回空目录；
- 新增字段只有字符串数组和两个小对象，`JSON.stringify(catalogue)` 无
  BigInt / 循环引用（`tools/test_catalog_wiring.mjs` 已有断言）；
- 旧的 `models/presets/ctxSteps/kvTypes/defaultKv/vramCeilingMiB/reasoning/
  budgets/defaultBudget/port/caps` 一个不少，旧界面的读取路径不变。

## 五、C. 缺失模型/构建引导（src/index.html）

### 5.1 触发与位置

- 位置：侧栏「模型」分组内、`#models` 列表上方；
- 触发：`CATALOGUE.models` 里任一条 `present === false` 或
  `binPresent === false`；
- 全部 `present` 且 `binPresent` 为真时整块 `#modelGuide` 隐藏。

### 5.2 DOM 结构与 id

```html
<div id="modelGuide" class="hidden">
  <div class="warn" id="guideStats"></div>
  <div class="note hidden" id="guideMissing"></div>
  <div class="note hidden" id="guideRoot"></div>
  <div class="note hidden" id="guideBuild"></div>
  <div class="btnrow"><button id="btnRescan" class="mini">重新扫描</button></div>
</div>
```

新增 id 全部唯一，且被内联脚本引用（`renderGuide()` / `rescanCatalogue()`）；
`$('...')` 引用由 `tools/check_ui.cjs` 自动核对，另外在
`tools/test_catalog_wiring.mjs` 里做了静态断言。

### 5.3 内容

1. **统计行**（`#guideStats`，`.warn`）：
   `缺 N 个模型文件 · 缺构建：有/无`；
2. **缺失文件**（`#guideMissing`，`.note`）：最多列 **3** 条路径，每条用
   `<code>`；超过 3 条只追加 `…另有 N 个`；
3. **建议模型目录**（`#guideRoot`，`.note`）：
   `建议模型目录：<code>{suggestedModelRoot.root}</code>。把 .gguf 放进该目录，
   或设置环境变量 <code>MODEL_STOVE_MODELS</code>（支持多个目录，用 `;` 分隔）。`
   `suggestedModelRoot` 为 null 时整块隐藏；
4. **构建提示**（`#guideBuild`，`.note`）：**仅当** `buildRoots` 为空且
   `buildBinary.present === false` 时显示：
   `把 <code>llama-server.exe</code> 放到构建根目录，或设置环境变量
   <code>MODEL_STOVE_BUILDS</code>（支持多个目录，用 `;` 分隔）`；
   若 `buildBinary.path` 有值，同时显示「当前默认构建路径：<code>…</code>（不存在）」；
5. **重新扫描**（`#btnRescan`，`.mini`）：调用
   `window.shell.refreshCatalogue()` → `ipcRenderer.invoke('catalogue:refresh')`，
   成功后重新 `window.shell.catalogue()` 并重绘模型列表、引导面板、预设、KV、
   上下文滑块与按钮。扫描期间按钮禁用并显示「扫描中…」，结束后恢复原文案。

保留选择：重扫后如果当前 `selModel` 仍然存在且 `present`，继续选它；否则回落到
第一个可启动模型并把 `selCtx` 置空（与换模型时的既有行为一致）。重扫失败时在
`#guideStats` 里显示错误并保持面板可见。

### 5.4 样式

`.warn` / `.note` 原本只在 `#settings` 下定义，本次把选择器扩成
`#settings .warn, #modelGuide .warn` 与 `#settings .note, #modelGuide .note`，
并新增 `#modelGuide` 的 code/list/btnrow 少量规则；观感与设置页提示一致。
所有路径/环境变量都用 `textContent` 填充，不拼 `innerHTML`。

## 八、未解决 / 已知限制

- 本环境不能启动 Electron GUI（DSH 下 mojo/IPC 限制），徽章与引导面板的
  真实渲染、点击「重新扫描」的视觉效果只验证到内联脚本语法、静态 id 检查和
  临时假 DOM；真机仍需在 Electron 窗口里看一遍。
- `buildBinary` 按需求优先 `config.BIN.stock`：本机 stock 存在，所以即使
  `buildRoots` 为空也会 `present=true`，此时构建提示不显示（这是任务 A 的定
  义，不是漏判）；换机器没有 stock 时才会回落到构建根/其余 BIN。
- legacy-only 且文件缺失的条目只显示「配置」徽章，没有 arch/ctx/size 可展示
  （P2 的事实：文件不在时没有 metadata）。
- 「重新扫描」仍是手动动作，没有文件监听；新增 GGUF 后要么点按钮，要么重开外壳。
- `tools/test_ctx_render.mjs` 在基线 `540800c` 上已有 2 项失败（场景 4 期望
  「切回 64K」而当前 `renderCtx()` 会按 q8_0 安全上限夹到 48K），与本次改动
  无关；该脚本不在本次验收列表，约束也不允许改其它 tools 测试，故未处理。
- 未改动的行为均已复跑：热接管/关窗保活/托盘、动态端口、能力门控、LAN 护栏、
  argv 快照、catalog 启动链路。

## 二、`Supervisor.tryAdopt()` 判定规则

签名：

```js
async tryAdopt({ healthCheck = this.healthCheck, timeoutMs = 2000, propsCheck = null } = {})
```

按顺序判定，**任一项不通过都不动进程、不清台账**：

1. **状态**：必须 `state === 'idle'` 且没有 handle，否则返回
   `{ adopted: false, reason: 'busy' }`（starting/ready/stopping/error 都算 busy）。
2. **台账**：`readLedger(this.ledgerFile)`；没有文件/空数组/所有项不合法 →
   `{ adopted: false, reason: 'no-healthy-leftover' }`。没有 `ledgerFile` 同样返回该原因。
3. **端口**：台账 `port` 必须是 `1..65535` 的整数，否则跳过该项。
4. **PID 身份**：用注入的 `processStartTime` / `pidAlive` 走
   `ports.checkLedgerEntry()`：
   - 有 `startedAt`：实际启动时间必须落在 ±30s 容差内，否则视为 PID 被复用 → 跳过；
   - 没有 `startedAt`（旧格式）：`alive` 即视为可认，但 `identity:'weak'`；
   - 探测不到启动时间（PowerShell 失败）→ 跳过。
5. **健康检查**：对 `http://127.0.0.1:<port>/health` 调用注入的 `healthCheck`。
   最多 **2 次**，总预算 `timeoutMs`（默认 2000ms），同时用注入时钟与真实
   `Date.now()` 双重截止；单次探测本身也套超时，探测抛错按失败处理。
   两次都失败 → 跳过。
6. **可选的二次校验**：`propsCheck(candidate)` 返回 falsy 或抛错 → 跳过。
7. 全部通过后构造不可变 adopted handle：
   `{ pid, startedAt: entry.startedAt || now(), exe, argvHash, port, generation: ++this.generation,
   logFile: null, logOffset: 0, url, modelId, preset, lanMode, adopted: true, identity }`；
   设置 `handle/lastPort/child=null`，通过 `_setState(READY)` 发事件。
8. **台账回写**：成功后保留台账并回写一次，带上 `modelId/preset/lanMode`。
   弱身份（原 `startedAt` 为 null）**继续写 null**，不能写 `now()` —— 否则下次
   启动会拿错误的启动时间做身份核对，把活进程误判成 `pid-reused`，
   既不接管也不收尸。

返回：

```js
{ adopted: true, status, identity }             // identity: 'strong' | 'weak'
{ adopted: false, reason: 'busy' | 'no-healthy-leftover' | 'error', error? }
```

整个函数包在 try/catch 里：任何异常都只返回 `adopted:false`，绝不阻断外壳启动。

配套改动：

- `ports.makeLedgerEntry()` 保留 `modelId/preset/lanMode`，`readLedger()` 读回同样字段；
- `Supervisor.start({ ..., lanMode })` 把 `lanMode` 写进 handle 与台账；
- `status()` 新增 `adopted`、`identity`、`lanMode`（`lanMode` 是 main.js 恢复
  current 所需；spawn 出来的 handle 为 `adopted:false, identity:null`）；
- `stop()` 对 adopted handle 走原有路径：`killProcess → _waitDead → 清台账 → idle`；
  adopted 没有 child，所以不存在 exit 事件误伤。

## 三、main.js 接线

### 3.1 启动热接管（whenReady）

顺序：`initRuntime() → createWindow() → adoptExistingServer(readyT0) → ensureTray()
→ killLeftoverProxy() → 自动启动代理 → 可选 autoStart`。

- 放在代理自动启动之前：`desiredProxyTarget()` 直接拿到被接管服务的动态端口，
  不会先指回 8091；
- 成功：按 adopted status 恢复 `current.modelId/preset/lanMode/startedAt`；
  `reasoning/budget/ctx/kv` 只存在于旧外壳 argv，无法从台账还原，置 null；
- 日志（可解析、带毫秒）：
  `[shell] 热接管已有服务 pid=... port=... (model=..., 用时 Xms, 启动链 Yms)`；
- 失败：写 `未发现可热接管的服务（reason，探测 Xms）`，窗口照旧显示未运行；
- 之后 `notifyRenderer()`；`notifyRenderer()` 也做了加固（win 不存在/已销毁/
  webContents 不可用都安全）。
- `startServer()` 开头仍是 `await stopServer()`：用户主动启动新服务时，先停掉
  被接管的服务再冷启动，行为正确。

### 3.2 关窗保活 + 托盘

- `keepServerOnClose()`：`settings.readSettings().keepServerOnClose !== false`，
  读设置异常也按 true（已定决策）。
- `win.on('close')`：非退出且保活开启 → `preventDefault()` + `win.hide()`。
  如果托盘创建失败，则**允许关闭**并置 `quitting=true`，由
  `window-all-closed` 停服务退出（退回旧行为，绝不留下无法唤回的隐藏窗口）。
- `ensureTray()`：`electron.Tray` + `Menu.buildFromTemplate`，图标
  `icon-256.png`（`nativeImage.createFromPath`，失败时退回路径）。
  菜单项：「打开窗口」「停止服务并退出」；双击托盘也打开窗口。
  整个创建过程 try/catch，失败只记日志并标记 `trayUnavailable`，不崩。
- `window-all-closed`：`!quitting && keepServerOnClose()` 时直接 return；
  否则 `quitting=true → stopServer + stopProxy → app.quit()`。
  退出清理用共享 `shutdownPromise`，避免托盘点击与 window-all-closed 重复收尸。
- `before-quit`：`quitting=true`，销毁托盘，保留原有 child kill 兜底。
- `app.on('activate')`：窗口不存在则 `createWindow()`，否则 `showWindow()`。
- `second-instance` 改为调用 `showWindow()`：窗口隐藏到托盘时第二次启动也能唤回。
- `settings:get/set` 顺带暴露 `keepServerOnClose`（只加字段，IPC 通道不变；
  界面本阶段未消费）。

### 7.2 A. 台账持久化更多状态 + 热接管还原

**台账字段**（`core/ports.js` 的 `makeLedgerEntry`）：

```
pid startedAt exe argvHash port generation modelId preset lanMode
logFile ctx kv reasoning budget          ← 本次新增
```

- `ctx` 只接受正整数；`logFile/kv/reasoning/budget` 只接受字符串，空串按缺失
  记 `null`。旧台账没有这些键时读出来就是 `null`，不会报错；
- `checkLedgerEntry()` 一行未改，身份判据仍是 `pid + startedAt`（±30s），
  弱身份规则（无 `startedAt` → weak）也不变；
- `Supervisor.start({ ..., ctx, kv, reasoning, budget })` 把这些值与 `logFile`
  一起写进不可变 handle 和台账；`status()` 新增 `logFile/ctx/kv/reasoning/budget`；
- `tryAdopt()` 构造 adopted handle 时逐项还原上述字段。旧台账缺字段 → `null`，
  不猜、不阻断接管；回写台账仍保留全部字段，下次重启继续可还原；
- `readLogTail(handle)`：先判 `handle.logFile`，为空直接 `[]`；文件存在正常读，
  路径不存在/读失败也返回 `[]`，不抛异常。

**main.js 热接管分支**：

- `current` 恢复 `modelId/preset/reasoning/budget/ctx/kv/lanMode/startedAt`；
  `ctx/kv/reasoning/budget` 在旧台账里没有时如实为 `null`；
- `shell.log` 逐项写来源，例如：

  ```
  [shell] 热接管状态还原: modelId=...（台账），preset=...（台账），
          reasoning=...（台账），budget=...（台账），ctx=65536（台账），
          kv=q4_0（台账），lanMode=false（台账），startedAt=...（台账）
  [shell] 热接管日志: <旧日志路径>（可读）
  ```

  缺失项写成 `reasoning=未知（旧台账无此字段）`；弱身份时 `startedAt`
  写 `当前时钟（旧台账无启动时间，弱身份）`；
- 「日志」面板：`logs` IPC 走 `supervisor.readLogTail()`，热接管后按台账
  `logFile` 读旧外壳那一次启动的日志；文件不存在时返回空数组，不报错。
  `status` IPC 额外带 `adopted/logFile/logAvailable/logReason`，界面在日志为空时
  显示「上次日志不可用（路径/旧台账没有记录 logFile）」，而不是只说一句
  「暂无日志」。

  在有 Electron 的桌面上过一遍。
- 台账记录的是 `startServer()` **请求值**；正常路径下与 `buildArgs()` 生效值一致
  （界面只发合法档位）。若绕过界面经 IPC 传入非法值，`buildArgs()` 会回落，
  而台账保留的是请求值 —— 下次热接管显示可能与实际 argv 有差异。这是有意的
  “不猜”取舍：不把回落逻辑复制到台账层。
- `logs` 面板为空时的说明依赖 `status` IPC 的 `logAvailable/logReason`；如果
  旧日志文件在接管后被外部删除，界面会按“不可用”显示，刷新后不会自动变成
  “有新日志”（adopted 进程不再写新文件）。
- 单实例锁、LAN 护栏、动态端口、catalog 接线、argv 快照、关窗保活/托盘兜底
  均未改动；本轮全部既有测试复跑全绿。

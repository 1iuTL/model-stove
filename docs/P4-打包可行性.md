## 七、已知限制（本轮未解决）

1. **asar 内路径与外置 Node 的冲突（最关键）**：`src/main.js` 里
   `REPO_ROOT = path.join(__dirname, '..')`，打包后是
   `resources\app.asar`；代理脚本路径是
   `resources\app.asar\context-proxy.mjs`，而启动代理用的是
   `spawn(nodeExe, [PROXY_SCRIPT], { cwd: REPO_ROOT })`。
   - 外部 `node.exe` 不能执行 asar 内的文件，`cwd` 也指向一个文件而非目录；
     真实启动代理时会失败（本轮没有启动进程，未取得运行期报错）；
   - `context-proxy.mjs` 还静态 `import './ui-inject.mjs'`，两者必须一起
     解包/放到真实目录；
   - 解决方向：`asarUnpack: ["context-proxy.mjs", "ui-inject.mjs"]`（或
     `extraResources`），并在运行时把路径映射到 `app.asar.unpacked`，
     再做真实进程验证。
2. **仍依赖系统 Node.js**：`findNodeExe()` 找不到 node 时会给
   “没找到 node.exe”的提示；本包没有携带 Node 运行时。正式分发要么要求
   用户安装 Node，要么把 `node.exe` 作为 `extraResources` 一起带上并调整
   `findNodeExe()`。
3. **`tools/allow-lan.ps1` 未打进包**：`files` 白名单没有 `tools/**`，
   但主进程在开 LAN 时引用 `REPO_ROOT/tools/allow-lan.ps1`；打包后该功能
   会因缺脚本失败。后续需把它加入 `extraResources` 或 `files`。
4. **防火墙规则展示路径过期**：`FW_RULES` 中 app 的 program 指向
   `REPO_ROOT/node_modules/electron/dist/electron.exe`，打包后该路径不存在，
   防火墙状态/规则检查会显示旧路径（不影响打包本身）。
5. **未签名、未改图标/版本资源**：exe 的 VersionInfo 仍是
   `FileDescription=Electron`、`ProductName=Electron`、
   `OriginalFilename=electron.exe`，图标也是 Electron 默认图标（因为
   `signAndEditExecutable: false`）。直接分发会触发 SmartScreen 提示。
6. **没有真实启动验证**：受 DSH 命名管道限制，Electron 在本环境启动即崩
   （见 `docs/P4-进度.md` 第九节），因此 asar 路径、托盘、代理、llama-server
   联动都未做运行期验证。
7. **`author` 缺失**：electron-builder 有警告；做 NSIS/Inno 前建议补上，
   同时补齐 `appId` / `productName` / 图标等元数据。
8. **未做安装器/签名/发布**：`dist/` 只有 `win-unpacked` 和
   `builder-debug.yml`，没有 `.exe` 安装器。

### 10.1 问题与修法

打包后主进程的 `__dirname` 在 `resources\app.asar` 内，于是
`REPO_ROOT = <...>\resources\app.asar`。普通 `require()` 有 Electron 的
asar 补丁，没问题；但这些是交给**外部进程**执行的：

| 文件 | 执行者 | 修复前路径 | 修复后路径 |
|---|---|---|---|
| `context-proxy.mjs` | 外部 `node.exe` | `app.asar\context-proxy.mjs` | `app.asar.unpacked\context-proxy.mjs` |
| `ui-inject.mjs` | 被上面静态 import | `app.asar\ui-inject.mjs` | `app.asar.unpacked\ui-inject.mjs` |
| `tools\allow-lan.ps1` | `powershell.exe` | `app.asar\tools\allow-lan.ps1` | `app.asar.unpacked\tools\allow-lan.ps1` |

外部 `node.exe` / `powershell.exe` 没有 asar 支持，读不到 `.asar`（它是个文件）。
修法分两层：

1. **运行时路径映射**：新增 `src/core/script-paths.js`（CommonJS 纯函数，无依赖）：
   - `resolveScriptRoot({ repoRoot, isPackaged })`：未打包返回 `repoRoot`；
     打包（`isPackaged === true` 或 `repoRoot` 以 `app.asar` 结尾）返回
     `repoRoot + '.unpacked'`；
   - `resolveScriptPath({ repoRoot, isPackaged, relative })`
     = `path.join(resolveScriptRoot(...), relative)`；
   - `src/main.js` 在模块加载期用 `app.isPackaged`（拿不到时按
     `REPO_ROOT` 是否以 `app.asar` 结尾兜底）算出 `SCRIPT_ROOT`，并用它设置：
     `PROXY_SCRIPT`（`context-proxy.mjs`）、`ALLOW_LAN_SCRIPT`
     （`tools\allow-lan.ps1`）、以及 `spawn(nodeExe, [PROXY_SCRIPT])` 的
     `cwd`（旧代码的 `cwd: REPO_ROOT` 在打包后指向一个文件，不是目录）。
   - **普通 `require()` 的路径一律未动**（`./config`、`./core/*`、
     `preload.js`、`index.html`、`icon-256.png` 等仍从 asar 读）。
   - 未打包时 `SCRIPT_ROOT === REPO_ROOT`，三个路径与旧代码逐字相同，
     源码运行行为不变。
2. **打包时解包**：`electron-builder.yml` 的 `files` 增加 `tools/**` 三个脚本，
   `asarUnpack` 增加外部进程实际需要的**完整依赖闭包**：
   - `context-proxy.mjs`、`ui-inject.mjs`；
   - `src/profiles.js`、`src/core/security.js`：`context-proxy.mjs` 用
     `createRequire(import.meta.url)` 按相对路径 `require('./src/profiles.js')`
     和 `require('./src/core/security.js')`，只解包入口而不解包它们会
     `MODULE_NOT_FOUND`（这是构建完静态检查才发现、必须一起处理的依赖）；
   - `tools/allow-lan.ps1`、`tools/allow-lan.cmd`、`tools/firewall-rules.ps1`：
     `allow-lan.ps1` 会 `. (Join-Path $PSScriptRoot 'firewall-rules.ps1')`，
     `allow-lan.cmd` 又会调 `allow-lan.ps1`，三者必须同目录同时存在。
   - `win.signAndEditExecutable: false`、`electronDist: node_modules/electron/dist`
     保持原样；构建不下载 Electron / winCodeSign / rcedit / NSIS。

新增 `tests/script-paths.test.mjs`（10 项）：未打包、`isPackaged=true`、

### 10.6 仍存在的限制

1. **仍依赖系统 Node.js**：`findNodeExe()` 只找 `MODEL_STOVE_NODE` /
   `C:\Program Files\nodejs\node.exe` / x86 / `%LOCALAPPDATA%`；包内没有
   `node.exe`。正式分发要么要求用户装 Node，要么把 node 作为
   `extraResources` 带上并改 `findNodeExe()`。
2. **未签名**：`win.signAndEditExecutable: false`，不做 Authenticode，
   直接分发会触发 SmartScreen / “未知发布者”。
3. **exe 元数据/图标仍是 Electron 默认**：未改 VersionInfo、未换
   `model-stove.ico`（同第七节第 5 条）。
4. **没有安装器**：只有 `dist\win-unpacked\`，无 NSIS/Inno 安装包。
5. **未真实启动 GUI**：受 DSH 命名管道限制，Electron 仍未启动；托盘、
   窗口、llama-server 联动、代理被主进程托管这条真实链路都未验证。本轮
   只证明了“外部 Node 能执行解包后的代理脚本并通过 HTTP 应答”。
6. **防火墙展示路径仍是旧路径**：`FW_RULES` 里 app 的 program 仍是
   `REPO_ROOT\node_modules\electron\dist\electron.exe`；打包后该路径不存在
   （状态展示会指错）。本轮未改是因为它不属于“外部进程执行的脚本路径”，
   且 `tools\allow-lan.ps1` 内部也硬编码了开发机路径（约束不允许改
   `tools/**`），单改正则会与脚本实际添加的规则不一致（同第七节第 4 条）。
7. **解包依赖清单需人工维护**：`asarUnpack` 只列了当前代理的依赖闭包
   （`ui-inject.mjs`、`src/profiles.js`、`src/core/security.js`）。以后
   `context-proxy.mjs` 若新增相对 `require()`，必须同步加入 `asarUnpack`；
   真实执行测试（10.4）是发现漏项的最直接手段。
8. **未验证 `allow-lan` 在打包后真的能提权加规则**：本轮只确认三个脚本
   被解包、路径解析正确、PowerShell 语法通过；UAC 提权属于交互操作，
   未在打包产物上点过。

> 本节完成后，第七节第 1 条（asar 内脚本外部不可执行）和第 3 条
> （`tools/allow-lan.ps1` 未进包）已解决；其余限制继续保留。

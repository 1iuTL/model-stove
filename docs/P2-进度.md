## 二、新增文件与 API

### `src/core/gguf.js`

纯 Node、CommonJS、可注入 `fs`，只读文件头与 metadata，绝不整文件读入内存。

```js
const gguf = require('./src/core/gguf');

const r = gguf.readGgufMetadata(file, {
  fs,             // 可注入；默认 require('fs')
  chunkSize,      // 默认 1 MiB
  maxMetaBytes,   // 默认 64 MiB；metadata 段硬上限
  maxStringBytes, // 默认 16 MiB
  maxKeyBytes,    // 默认 64 KiB
  maxArrayItems,  // 默认 4096（大数组只保留前缀）
  maxKvCount,     // 默认 1e6
});
// r = { ok, version, tensorCount, kvCount, metadata, architecture, error,
//       truncated, truncatedKeys, truncatedInfo, metaBytes, fileSize }
```

派生 helper（全部容错，不抛异常）：

```js
gguf.getArchitecture(meta);      // general.architecture，缺失时从 <arch>.* 反推
gguf.getContextTrain(meta);      // <arch>.context_length
gguf.getBlockCount(meta);        // <arch>.block_count
gguf.getHeadCount(meta);         // attention.head_count；数组取最大值
gguf.getHeadCountKv(meta);       // attention.head_count_kv
gguf.getEmbeddingLength(meta);   // <arch>.embedding_length
gguf.getExpertInfo(meta);        // { count, used, shared } 或 null
gguf.getChatTemplate(meta);      // tokenizer.chat_template 或 null
gguf.isThinkingTemplate(tpl);    // 启发式：think / reasoning / enable_thinking / <|think|>
gguf.describeGguf(file);         // 目录摘要，失败也返回字段齐全的对象
```

`describeGguf()` 返回：

```js
{ ok, arch, ctxTrain, blockCount, experts, headCount, headCountKv,
  embeddingLength, thinking, chatTemplateBytes, sizeBytes,
  version, tensorCount, kvCount, truncated, error }
```

实现要点：

- 支持 GGUF v2/v3；magic 校验、版本校验、u64 计数安全转换；
- 元数据值类型 0..12 全支持；u64/i64 返回 **BigInt**（不丢精度）；
- 字符串 = u64 长度 + UTF-8；数组 = u32 元素类型 + u64 长度 + 逐项；
- 1 MiB 顺序缓冲；长字符串按需直接读；所有读取前做文件边界检查，
  越界统一报“遇到 EOF（偏移/需要字节/文件大小）”；坏文件只返回 `ok:false`；
- metadata 段默认 64 MiB 上限：超过直接报“元数据过大”，不继续扫；
- 大数组默认只保留前 4096 项（tokenizer tokens/merges 等），剩余项只做结构化
  跳过，不分配内存；`truncated:true` + `truncatedKeys` + `truncatedInfo`
  记录原长度/保留数；
- `<arch>.<suffix>`、`llama.<suffix>`、`general.<suffix>`、任意 `*.<suffix>`
  多级兜底，兼容上游和 fork 的键名差异；
- 不解析 tensor 信息（metadata 结束即返回），只返回 tensor 计数。

### `src/core/catalog.js`

```js
const catalog = require('./src/core/catalog');

catalog.scanModelRoots(roots, { maxDepth: 3, fs, warnings })
// -> { entries: [{ file, dir, realPath, sizeBytes, mmproj }], roots, warnings }

catalog.buildCatalog(entries, { nameOf, overrides, warnings, describe, ... })
// -> [{ id, name, file, dir, sizeBytes, mmproj, arch, ctxTrain, blockCount,
//       experts, thinking, quantization, available, source, overrides, ... }]

catalog.importLegacyConfig(config.MODELS)
catalog.mergeCatalog(scanEntries, legacyEntries, { overrides })
catalog.discoverCatalog({ roots, legacyModels, overrides, nameOf, maxDepth, ... })
// -> { models, roots, warnings, scannedAt }
```

行为约定：

- **深度**：根目录文件算 0 层；默认 `maxDepth=3`，即最多进到第 3 层子目录；
- **忽略**：`.` 开头（hidden）、`.parts/`、`.tmp/`、`*.part`、`*.tmp`；
  `mmproj*.gguf` 不作为独立模型，只作为同目录视觉投影候选；
- **mmproj 配对**：同目录优先文件名含 `Q8_0` 的，否则按名称排序取第一个；
  不跨目录配对；
- **去重**：条目按 realpath（Windows 小写）去重；重叠根、重复根写法都只收一次；
- **id**：`sha1(规范化 realpath).slice(0, 12)`；同一文件多次扫描稳定；
- **name**：默认文件名去掉 `.gguf` 与末尾量化后缀（如 `-Q4_K_M`）；
  `options.nameOf` 可传函数或映射覆盖；
- **旧配置导入**：`safeCtx/maxCtx/probeTps/bin/extraArgs/temp/topP/topK/mmproj/
  kvLayers/defaultPreset/name/note` 全部保留在 `overrides`；文件不存在也保留条目
  并置 `available:false`，旧 id 记在 `overrides.legacyId` 与顶层 `legacyId`；
- **合并**：按 realpath；legacy 命中 scan 时覆盖 name/note/mmproj 与 overrides
  （显式 `options.overrides` 优先级更高），scan 未发现的 legacy 条目原样保留；
  scan 条目 `source:'scan'` + `legacy:true`，仅 legacy 条目 `source:'legacy'`；
- **排序**：按 name 小写 → name 原文 → id，不依赖 locale，结果确定；
- **warning**：`root-missing` / `root-not-directory` / `scan-error` /
  `file-unreadable` / `metadata-error`。坏文件只加 warning，不抛错、不丢条目。

## 七、未解决 / 已知限制

- **hidden 判定只认 `.` 前缀**，不读 Windows 隐藏属性（Node 无跨平台 API）；
- realpath 去重不能识别硬链接（同一 inode 不同路径 realpath 仍不同）；
- `quantization` 只从文件名提取（`Q4_K_M`/`Q8_0`/`F16` 等），未映射
  `general.file_type` 数字枚举 —— 后者在不同 llama.cpp 版本里含义有漂移风险；
- metadata 段超过 64 MiB 时整条元数据解析失败（条目仍保留、`available:true`、
  带 `metadata-error` warning），这是防 DoS 的硬边界；
- 大数组默认截断到 4096 项；catalog 需要的 arch/ctx/block/head/expert/模板
  都是标量或小数组，不受影响；
- 仅解析 metadata，不解析 tensor 信息（只返回 tensor_count）；
- mmproj 是“同目录、所有模型共用”的粗配对；一个目录放多个模型+多个 mmproj
  时不做更细的映射；
- legacy-only 且文件存在于 scan 根之外的条目，目前只补 `available/sizeBytes`，
  不解析 metadata（接线时可再调 `describeGguf`）；
- 真实测试依赖本机 `D:\Qwen3.8-35B-A3B-Distill-Abl`，换机器会条件 skip。

### 8.2 运行时模型对象（任务 B）

`runtimeModels()` 把 catalog 条目映射成与既有 `buildArgs()` / 界面兼容的对象：

- `id`：有 `legacyId` 的条目（旧配置命中，或 scan 合并到旧配置）沿用旧 id，
  `qwen38distill-abl` 等设置值不变；scan-only 用 catalog 的
  `sha1(realpath).slice(0,12)`；
- 旧字段全部取自 `entry.overrides`（`safeCtx/maxCtx/probeTps/bin/extraArgs/
  temp/topP/topK/mmproj/kvLayers/defaultPreset/note`），`defaultPreset` 缺省
  `text-64k`，`safeCtx/maxCtx` 缺失给 `null`（由 UI 滑块与 `buildArgs()` 的
  既有回落处理）；
- **bin 解析顺序**（scan-only 能启动的关键）：
  1. `overrides.bin` 指向的文件仍存在；
  2. `paths.buildRoots`（`MODEL_STOVE_BUILDS` / `config.builds.roots`）里的
     `llama-server.exe`：先根目录，再按名称排序的一层子目录；
  3. `config.BIN` 里第一个存在的构建（stock → prism → fast）；
  4. 都没有 → `bin:null, binPresent:false`，`warn` 明确提示设置
     `MODEL_STOVE_BUILDS` 或补齐 `BIN`；
- `meta` 只含安全摘要 `{ arch, ctxTrain, blockCount, experts, thinking,
  chatTemplateBytes }`；**绝不**把 `readGgufMetadata().metadata` 放进 IPC
  （BigInt + 可能几十万条 tokenizer 词条）。测试里对整份 catalogue 响应做了
